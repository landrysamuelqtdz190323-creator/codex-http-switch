# 兼容性与验收范围

## 目标用户

第一版面向使用 ChatGPT 登录、连接 OpenAI 官方 Codex 后端的用户。Python 3.11+；在线验证还需要一个支持 `exec --ephemeral --json` 的官方 Codex 客户端。macOS 桌面内嵌客户端、独立 CLI 和 Windows 的路径不同，自动发现失败时用 `--codex` 指定客户端。

API-key 登录、自定义厂商/中转地址默认拒绝自动切换。钥匙串登录可能无法仅从 auth.json 推断，使用 `--auth-mode chatgpt` 是用户对既有登录方式的声明，不是登录、迁移或创建凭证。

## 哪些情况不能称为“已修好”

| 观察 | 可以说明 | 不能说明 |
| --- | --- | --- |
| 普通网页或视频能打开 | 对应请求可用 | Codex 长连接、同一路由或账号接口可用 |
| plan/config-valid | 指定用户文件包含工具认识的配置 | 桌面当前会话已采用它 |
| 模型列表可读、HTTP 200 | 某个接口返回结果 | 推理完整结束 |
| probe-passed | 该次短 CLI 推理完成、收到预期消息、未观察到流式重试 | 长任务、Dot、托管工具和桌面所有功能均正常 |
| 原任务重启后完成 | 当前版本和条件下该任务可用 | 任意网络、版本和任务均稳定 |

自定义 HTTP provider 可能影响桌面能力或功能展示，见研究报告中的官方问题记录。现有会话、项目级配置、启动参数、组织托管配置有自己的优先级；不能只读取用户 config.toml 就宣称已经掌握所有有效配置。

## 本地验证与 CI 的区别

发布前本地运行了配置生命周期、冲突恢复和隐私相关单元测试，并对现有 HTTP 配置执行只读检测。本机此前已完成同机制的真实短 CLI 请求，但没有把个人原始日志或响应发布进仓库。仓库不含真实凭证。

在线验证由用户显式执行 `verify --online`。没有对所有 Codex 版本和所有桌面功能作认证。CI 在各操作系统上运行单元测试；网络、钥匙串、组织策略和长任务仍需目标环境实测。

## 保留与回滚

恢复只处理本工具拥有的字段。用户改过提供商选择或自有条目时会拒绝操作，避免覆盖意图。备份校验失败、文件不是有效 TOML、配置是符号链接或并发编辑被检测到时，也会停止写入。

锁文件不代替操作系统安全边界。只有本工具的进程会遵循它；外部编辑器仍可能在极短窗口同时写入。操作前避免在多个窗口编辑同一配置。备份目录和完整配置可能含敏感信息，请勿上传。
